# help-desk

Локальное браузерное приложение для анализа TXT-отчётов сравнения/объединения 1С.

## Что сделано

- Загрузка отчёта `.txt` напрямую в браузер.
- Авто-декодирование UTF-16LE (формат, в котором обычно выгружается отчёт 1С).
- Парсинг структуры отчёта:
  - иерархия объектов по табуляциям и строкам `- ...`;
  - блоки конфликтов `Изменено: X - Y`;
  - блоки `Объект присутствует только в основной конфигурации`;
  - блоки `Объект присутствует только в файле`.
- Группировка по объектам и оценка риска конфликтов (низкий/средний/высокий).
- Фильтрация по риску, полнотекстовый поиск, список всех конфликтов объекта.
- Ручное разрешение каждого блока (`левая`, `правая`, `склеить`, `отложить`).
- Экспорт итогового `resolved.txt`.
- Сохранение/загрузка сессии разрешений в JSON.

## Формат отчёта (анализ TestReport)

На примере `test_documents/TestReport.txt`:

- Файл имеет BOM UTF-16LE.
- В начале идёт легенда маркеров:
  - `***` — объект изменён;
  - `-->` — есть только в основной конфигурации;
  - `<--` — есть только в файле;
  - `^-` — изменён порядок.
- Иерархия задаётся отступами (табуляцией) и строками вида `- ...`.
- Детализация отличий содержит блоки с диапазонами строк, затем контент отличий:
  - строки `< ...` (левая сторона);
  - строки `> ...` (правая сторона);
  - строковые литералы в кавычках.

## Запуск

Откройте `index.html` в браузере.

Для локального сервера:

```bash
python -m http.server 4173
```

И затем откройте: `http://localhost:4173`.

## Ограничения текущей версии

- Экспорт создаёт резолв-результат в человекочитаемом виде по конфликтным блокам (а не пересобирает исходный отчёт построчно).
- Эвристики парсинга универсальные для типовых 1С merge-report, но для экзотических вариаций формата могут потребоваться дополнительные правила.
